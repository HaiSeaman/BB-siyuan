## v1.4.0

**主题：从「只能聊天」变成「聊天 + 生图」，并把生图这一路的坑全填平。**

这一版不是一次小改：新增了完整的生图模块，之后又经过多轮实测与全仓审查，修掉了 20 多个真实问题。下面按主题分组，不按修复轮次编号。

---

### 新增：生图

顶栏模型名点开，清单里画图模型会带一个橙色的「画图」标签。点它，面板自动进入**生图模式**：

- 提示词条和 MCP 条自动收起（图片模型不吃系统提示，也不会调工具）
- 输入框的「发送」变成「生成」
- 顶栏那个小圆点从绿变橙，一眼看出现在是哪套
- 控制条最末有一个「💬 对话」按钮，点一下切回上次用的聊天模型

生产走 OpenAI 标准接口：`/images/generations`（文生图）、`/images/edits`（图生图，multipart）。也认服务商只给网址的情况。

### 新增：输入框上方四个按钮

从左到右：**图片 / 上传 / 大小 / 尺寸 / 优化**

| 按钮 | 作用 |
|---|---|
| **图片** | 直接打开自动保存图片的文件夹（资源管理器）。手机端会给出路径。 |
| **上传** | 选一张本地图当参考图（PNG/JPG/WEBP，8 MB 以内），有参考图时走图生图。 |
| **大小** | 1K / 2K / 4K / 4K+，菜单里直接显示长边像素。 |
| **尺寸** | 10 种常用比例：1:1、4:3、3:4、16:9、9:16、3:2、2:3、5:4、4:5、21:9。 |
| **优化** | 用**聊天模型**把输入框里的话改写成一段中文提示词，直接填回输入框。 |

控制条上一直显示这次会出多大的图，例如 `2560 × 1440`。选 4K 但模型不吃时，会变成橙色的「实际 1536 × 1024（已换）」，明确告诉你换成了什么。

### 新增：图片存进插件数据文件夹

每张生成的图片自动写到：

```
<工作空间>\data\storage\petal\siyuan-plugin-ai-chat\images\
```

- 图片**不会**塞进 `sessions.json`。存档里只记路径、尺寸和提示词 —— 否则一张 4K 图的 base64 就有十几兆，历史会越用越慢。
- 关掉面板再打开、重新打开历史对话，图片都还在。
- 删单个历史 / 清空全部历史时，对应的图片文件会一起删掉。
- 存文件失败时，图片仍然显示在对话里，并提示你用「保存到电脑」自己存一份。

### 新增：每张图下面两个按钮

| 按钮 | 行为 |
|---|---|
| **复制图片** | 把图片本身放进剪贴板（不是复制文字）。手机等不支持的环境会明确告诉你改用「保存到电脑」。 |
| **保存到电脑** | 桌面端弹**原生另存为**对话框；手机端走系统下载。 |

### 新增：一个 API 里多选模型

模型名前加了一个勾选框，勾几个顶栏就显示几个：

- 可以勾多个，点名字随时切
- 没勾的名字在设置页里变淡
- 正在用的那个不能取消勾选（否则顶栏名字会消失），会提示先切走
- **老配置升级上来默认全勾**，行为不突变

### 新增：记住上次用的聊天模型

顶栏切到画图模型后，「优化」还要用会写字的模型。插件另外记一份"上次选中的聊天模型"：

- 点任何一个聊天模型时自动记下
- 点「优化」时优先用它
- 它被删掉了就退到第一个能聊天的
- 一个聊天模型都没有时，直接告诉你「去设置里加一个」，不会拿画图模型去发一次注定失败的请求

### 改进：尺寸档位改成按屏幕分辨率

原来的 1K 是「长边 1024」，选 1K + 16:9 只出 1024×576，铺不满屏幕。现在按消费级叫法：

| 档位 | 16:9 | 1:1 | 9:16 | 铺满什么屏 |
|---|---|---|---|---|
| **1K** | 1920×1080 | 1920×1920 | 1080×1920 | 1080p / 普通笔记本 |
| **2K** | 2560×1440 | 2560×2560 | 1440×2560 | 2K 显示器 |
| **4K** | 3840×2160 | 3840×3840 | 2160×3840 | 4K 显示器 / 电视 |
| **4K+** | 4096×2304 | 4096×4096 | 2304×4096 | 电影 DCI 4K |

短边按比例算并凑成 8 的倍数。已用真实服务商实测：1920×1080、2560×1440、3840×2160 全部生成成功，文件大小随尺寸递增。

### 改进：模型的三分类

以前从接口拉模型时，`dall-e`、`gpt-image`、`flux` 这些会被当成"不能聊天"直接滤掉 —— 那是对的（聊天确实不能用），但副作用是**生图功能根本没有模型可选**。

现在分三堆：

- **聊天模型**：正常列出来
- **画图模型**：橙色底，带「画图」标签，点它就进生图模式
- **用不了的**：嵌入、语音这类，虚线灰底，明说"选了会报错"

设置页的模型清单也按这三堆分组显示；「清除其他模型」不会再顺手清掉画图模型。

### 修复：`gemini-3.1-flash-image` 这类模型认不出来

识别规则原来是逐个列举（dall-e、gpt-image、flux、sd……），漏了名字里带 `image` 的一整类 —— 而 Gemini 的图片模型正好都在这一类里。表现是：

- 点「🎨 生图」提示「还没有画图模型」（明明配了）
- 4 个按钮一个都不显示
- 这个模型被当成聊天模型，发给它会 400

现在：**名字里带 `image` 就算画图模型**，再补上 diffusion / pixart / hidream 等系列。同时保留防误判：带 `chat`、`vision`、`-vl` 的多模态模型（如 `gpt-4o`、`qwen-vl-max`）仍然算聊天。

**兜底**：设置页每个模型名旁边多了一个「标为画图 / ✓画图」小按钮。遇到任何认不出来的名字，点一下就手动指定。

### 修复：4 个按钮以前一个都看不到

这批按钮原来只在「生图模式」下渲染，而生图模式又要求当前模型被认成画图模型。名字没认出来 → 模式没进 → 按钮全没了。

现在：**4 个按钮常驻**，对话模式和生图模式都在，位置在**思考档位的右边**。

### 修复：图片「能复制能保存，但看不见」

两个原因叠在一起：

1. **文件类型是假的**：服务商给的是 JPEG，data URL 里却写着 png，插件照着起名 `.png`。思源的部分版本会拒绝渲染"声明成 png 其实是 jpeg"的图 —— 而复制/保存走原始字节所以正常。
2. **模板不会重算**：模板里写的是 `imageSrc(img)`。Svelte 看不到函数内部读了图片缓存，缓存更新后模板不重渲染，图一直停在最早那个读不到的地址上。

现在：按文件头字节判断真实类型（JPEG/PNG/WebP），存图时就用正确的后缀；模板改成查一张响应式映射表，数据一到位立刻重渲染。历史里的老文件会在打开会话时自动按真实类型改名并更新引用。

### 修复：正文里的图片只当文字，没有保存按钮

有的服务商（Gemini 系）把图塞在文字回复里返回：

```text
![image](data:image/jpeg;base64,...)
```

以前它只会当文字渲染，底下一个通用「复制」，既没法保存，base64 还把存档撑到 1MB。现在会被自动抽成图片卡片，大图搬进 `images/`，正文里的 base64 摘掉。

### 修复：「图片」按钮打不开文件夹

`dataDir` 在思源里已经是 `Z:\siyuan\data` 这一层，代码又多拼了一段 `data\`，得到 `Z:\siyuan\data\data\storage\...`，目录不存在必然失败。

现在按 `dataDir` 最后一段判断，兼容"已到 data 层"和"只到工作空间根"两种情况；打开方式也加了四层兜底（`@electron/remote` → `electron` → `explorer.exe` → 显示路径），手机端明确说明不能打开。

### 修复：一键清除模型会把勾选的也删掉

原来的清除逻辑只保留"当前用着的那个 + 画图模型"，**完全不看勾选列表**。勾了 5 个，一点清除只剩 1 个。

现在保留三类：**勾选的** + **画图模型** + **当前在用的**，只清"既没勾也没在用"的。确认框会写明保留了几类。

### 修复：生图的四个并发与超时问题（审查发现）

1. **生图结束后无条件清 `generating`**：点停止后立刻再点生成，旧一轮稍后结束会把新一轮的按钮提前解锁 → 能重复发送、并发两轮。
2. **「停止」是假停止**：用 `Promise.race` 模拟，底层请求还在跑满 5 分钟，白烧流量和额度，落败的 promise 还会变成未处理的 rejection。现在 `fetchBinary` 真正支持 `AbortSignal`。
3. **`fetchOnceViaNative` 忽略传进来的超时**，硬编码 60 秒 → MCP 的慢请求被莫名判超时。
4. **`streamViaNative` 没有超时** → 服务端连上却不发数据时，界面永远卡在「正在生成」。现在统一 5 分钟兜底。

### 修复：其他中危问题

- **停止后空白的占位气泡留在界面上**（存档又会过滤掉它，两边不一致）→ 现在停止时一并清掉。
- **正文插图搬盘时文件名固定写 1** → 同一条消息里的多张图会同名互相覆盖，直接丢图。现在带序号。
- **`onDestroy` 只中止生图，没中止聊天流** → 面板销毁后流还在跑并往已销毁的组件写状态。
- **优化提示词时漏传手动标记名单** → 手动标成画图模型的会被选去优化，必然失败。
- **网址图片不校验字节** → 服务商返回 JSON 错误体时会被当成图片存下去，得到一个打不开的文件。
- **整理正文图片后没保存** → 搬盘结果丢失，下次打开又要重搬，存档里的 base64 也一直留着。

### 整理：合并重复实现

- **三份 mime 推断**合成一份（`mimeOfName`），另两个变别名
- **两份 base64 分块编码**合成一份（`bytesToBase64`）
- **两个 68 行的请求函数 63 行重复**，合并成 `runNativeRequest`
- 删掉无人使用的 `modelKindLabel`
- 去掉同一表达式里重复调 4 次的 `computeSize` 和一个无效三元

### 修复：官方尺寸表误伤第三方模型

原来用 `/gpt-image/i` 匹配，把 `gpt-image-2.6-sunburst` 这类第三方模型也当成官方 `gpt-image-1`，强行把 2560×1440 换成 1536×1024。现在只锁精确的官方名，第三方不受限。

## v1.3.0

**主题：我发的消息能复制/原地重发 + 拉来的模型点了就能用 + 一键清空历史**

### 新增：我发出的消息多了两个按钮

- **复制**：点一下就复制自己发的那句话，不用手划选。
- **重发**：点一下用这条原话重新生成，回答**直接替换原来那一条**。

重发**不会新增**一组消息。发给模型的历史也只截到这条之前，否则等于让它看着自己的旧答案再答一遍。

### 修复：从接口拉来的模型，选中后用不了

三个原因叠在一起：

1. **点模型名不会真的切过去**：只改了「这套 API 记住哪个模型」，没改「当前用哪套 API」。
2. **拉取后偷偷选中清单第一个**：中转站头一项常是 `text-embedding-3-small`，自动选中必然报错。
3. **清单里混着不能聊天的模型**：`embedding`、`whisper`、`tts`、`rerank`、`dall-e`、`flux`。

现在：点模型名会连 API 一起切；拉取只往清单里加、不自动选；不能聊天的会被滤掉并告知跳过了几个。

### 改进：「清除所有模型」改为「清除其他模型」

只清**没选中**的，当前选中的一定保留。

### 新增：历史对话一键清空

历史抽屉里多了「清空全部历史（N 个）」，二次确认后全部删掉。当前正在聊的内容也会一起清空，否则下一轮生成又会把它存回历史。

### 文档

- `README.md` 改为完整英文版，新增 `README.zh-CN.md` 完整中文版
- 新增 `docs/RELEASE-v1.3.0.md`
- `.gitignore` 补齐并加注释
